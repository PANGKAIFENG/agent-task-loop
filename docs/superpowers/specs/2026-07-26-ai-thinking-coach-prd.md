**本期只解决：在用户决定本周重点之前，由 AI 基于用户授权的个人上下文进行研究式澄清与启发，并把用户最终确认的判断沉淀为可复盘的周度记录。**

## 1. 模块定位

“本周思考教练”位于 ClawVault 个人首页的决策层，帮助用户先想清楚“本周真正值得解决什么、为什么值得、预期产生什么结果”，并把判断留在 Obsidian。

它不替用户选择三件最重要的事，也不把已有任务重新包装成答案。它通过事实整理、信息缺口识别和方案对比，帮助用户形成自己的判断；确认后的周度判断成为可人工查看和填写复盘结果的事实记录。

现有规则型 Top 3 继续作为“当前执行任务”展示，回答“系统里现在正在推进什么”；本模块回答“本周最值得投入什么”。两者同时存在但不能混为一谈。

## 2. 功能目标

### 2.1 用户价值

- 从“为了填满 Top 3 而产生任务”转向先判断结果价值与机会成本。
- 在目标、项目、任务、日程和历史复盘之间建立可核对的决策背景。
- 在上下文不足时得到高质量问题和调研方向，而不是得到貌似确定的答案。
- 将对话结果留在 Obsidian 中，周末可人工核对承诺与实际结果。

### 2.2 AI 价值

- 整理已知事实、假设与缺失信息，降低用户自己拼接上下文的成本。
- 用渐进式追问帮助用户识别预期结果、真实价值、优先级依据和“不做什么”。
- 对可能方向提供依据、代价和验证方式，不替用户做最终排序。
- 将用户确认后的判断整理成稳定、可编辑、可复盘的结构化总结。

### 2.3 成功标准

- 用户能在一次教练会话中形成至少一个自己确认的本周判断，或明确决定“本周暂不设重点”。
- AI 输出中可区分事实、假设、缺失信息和建议，不把推测写成用户结论。
- 未经用户确认，不创建任务、不改任务状态、不写入正式周度重点。
- 已确认的周度记录可以在 Obsidian 中读取、编辑复盘区，ATL 后续保存不会覆盖受控区外的人工内容。
- AI、模型或授权上下文不可用时，个人首页和人工任务管理仍可正常使用。

### 2.4 非目标

- 不让 AI 自动决定本周最重要的三件事。
- 不自动创建、拆解、排期、执行或完成任务。
- 不自动修改目标、OKR、项目、日历或既有复盘内容。
- 不在本期建立完整的目标管理系统或 OKR 评分系统。
- 不保存完整对话逐字稿作为默认长期记忆。
- 不引入第二套模型凭据或服务配置。
- 不实现 Agent、小队或 Skill 的自动编排。

## 3. 用户场景

### 3.1 周初还不知道什么最重要

用户打开个人首页，看到很多在办项目和候选任务，但无法判断本周应集中在哪。用户启动教练，授权目标、项目、任务、日历和周复盘。AI 先呈现已知事实与缺口，再逐步追问预期结果、时间窗口、机会成本和成功证据。用户最终确认一项或多项本周判断，并写入周度记录。

### 3.2 有一个想法，但不确定值不值得做

用户输入“我是不是应该做 X”。AI 不直接回答“应该”，而是研究这个选择与当前目标、项目状态和本周容量的关系，提出成立条件、替代方案和最低验证动作。用户可确认继续、暂缓、停止，或保留为仍需调研的判断。

### 3.3 后续场景：周末复盘实际价值

周、月、季度复盘自动读取和聚合本周记录不属于 `v0.7.0`。本期只在周度文件中预留人工复盘区，后续版本再接入自动复盘消费者。

## 4. 双轨协作定义

| 阶段 | 人工动作 | AI 动作 | 系统反馈 | 边界 |
| --- | --- | --- | --- | --- |
| 发起 | 点击“开始本周思考”，输入当前困惑或想讨论的方向 | 不预设用户目标，不提前给 Top 3 | 显示本周状态、现有记录和可授权资料 | 空白输入也可从现有目标开始，但不得自动确认 |
| 授权 | 勾选允许本次读取的上下文 | 说明每类资料能帮助判断什么 | 显示本次发送范围和当前模型 | `笔记同步助手`、`每日所思`每次会话都需单独勾选 |
| 研究 | 查看并纠正背景摘要 | 整理事实、假设、缺失信息和资料来源 | 显示“正在整理背景”及引用来源 | 未授权资料不可读取；笔记内容只作为资料，不作为系统指令 |
| 启发 | 回答一个问题、调整授权或转人工整理 | 每轮只提出一个问题，不一次抛出长问卷 | 显示已澄清内容、仍缺信息和可暂停状态 | 不用统一评分替代用户判断 |
| 方案比较 | 补充偏好、约束和担忧 | 提供可能方向、成立条件、代价、机会成本和验证方式 | 清晰区分“AI 观察”与“用户表达” | 不把建议表述成用户已决定 |
| 判断确认 | 编辑并确认自己的本周判断、预期结果与不做事项 | 复述判断，检查是否存在关键矛盾或无法验证的结果 | 显示确认前预览 | 未确认时只能保存草稿，不得生成正式任务 |
| 沉淀 | 确认写入或继续修改 | 整理结构化周度总结和关键回答 | 显示文件位置、状态和可继续编辑入口 | 默认不保存完整聊天记录 |

## 6. 主链路与阶段流转

1. **发起本周思考**：用户从个人首页进入教练，输入困惑、候选方向或希望澄清的问题。
2. **选择授权上下文**：默认可选目标、项目、任务、日历和周复盘；敏感来源按次显式授权。
3. **整理事实与缺口**：AI 返回事实、假设、缺失信息和来源，用户可纠正。
4. **提出当前问题**：AI 根据缺口提出优先澄清的 1 个问题，不把思考维度做成长问卷。
5. **渐进式教练对话**：用户逐步回答；AI 每轮先吸收答案，再决定继续追问或进入方案比较。
6. **整理方案与判断依据**：AI 汇总考虑过的方向、成立条件、收益、成本、机会成本、风险和验证证据。
7. **用户确认最终判断**：用户自行确认本周真正想解决的问题、希望产生的结果、本周承诺和本周不做。
8. **写入周度记录**：系统保存用户确认后的结构化总结，并预留人工周末复盘区。

如果上下文不足，用户可调整授权或继续回答；如果暂不确认，只保存草稿；如果 AI 失败，保留输入并允许重试或转人工继续。

## 7. 页面结构与信息布局

### 7.1 个人首页总览

首页不常驻完整教练工作区。入口位于“当前最值得推进的三件事”标题栏右侧，与三张重点卡片处于同一视觉层级：

1. **本周未开始**：按钮显示“梳理本周重点”。
2. **已有未确认草稿**：按钮显示“继续本周思考”。
3. **本周已确认**：按钮显示“查看本周判断”。
4. **确认前的三张卡片**：继续显示现有规则产生的系统候选任务，明确它们不是 AI 结论。
5. **确认后的三张卡片**：刷新为用户确认的 0 至 3 项本周判断；若用户确认本周不新增重点，则显示该决定，不伪造任务。

Personal Pulse、任务统计和其他首页区域保持现状，不因教练功能改变顺序或可用性。

### 7.2 教练入口状态

| 状态 | 页面呈现 | 主操作 |
| --- | --- | --- |
| 本周未开始 | 标题栏右侧单一入口，不增加常驻说明区 | 梳理本周重点 |
| 思考草稿 / 等待确认 | 标题栏右侧显示草稿状态入口 | 继续本周思考 |
| 已确认 / 已复盘 | 三张卡片展示用户确认判断，标题栏保留入口 | 查看本周判断 |

### 7.3 教练对话弹窗

- 点击标题栏入口后，在 Obsidian 内打开约 `960 × 700px` 的居中大弹窗；不打开浏览器、系统窗口或新的 Obsidian 标签页。
- 顶部显示当前周次和当前模型；授权区持续显示本次可选资料，关闭入口沿用 Obsidian 原生弹窗。
- 背景区使用可展开摘要展示事实、假设、缺失信息和来源，不与对话混成一段长文本。
- 主区每轮只突出一个核心问题，不强迫用户一次填完多个维度。
- 用户可以选择“回答并继续”“调整本次授权”“整理我的判断”“保存草稿”或关闭暂存。
- 方案整理后明确提示“这是对用户表达的整理，不是 AI 替用户决定”。
- 确认前展示周度记录预览，所有内容可编辑。
- 关闭弹窗时保留未确认草稿；用户确认后关闭弹窗并刷新首页三张重点卡片。

## 9. 关键交互逻辑

### 9.1 上下文授权

- 默认上下文选择器包含：目标、项目、任务、日历、周复盘。
- 系统显示可授权资料类别，并允许用户逐类勾选或取消。
- `笔记同步助手`与`每日所思`不默认读取；用户每次启动教练时显式选择后，仅本次会话有效。
- 只有被选择且可解析的内容进入当前模型；未选内容不进入提示词或总结。

### 9.2 教练研究与提问原则

AI 使用以下维度构建问题地图，但不把它们变成固定表单或机械打分：

- **目标关联**：与季度、月度、项目目标或个人长期方向有什么关系。
- **预期结果**：做完后具体会改变什么，谁能观察到，证据是什么。
- **价值与杠杆**：是一次性产出、减少长期重复消耗，还是打开后续机会。
- **时机与窗口**：为什么是本周；延后一周会失去什么，或其实没有真实紧迫性。
- **机会成本**：选择它意味着本周放弃、暂停或减少什么。
- **可行性与依赖**：所需时间、精力、授权、协作人和前置条件是否具备。
- **不确定性与验证**：哪些是事实，哪些是假设；能否先做低成本验证。
- **个人可持续性**：当前精力、生活恢复和工作负荷是否支持该承诺。

AI 每轮优先提出最能改变判断的一个问题。若需要外部调研，本期先说明调研问题、所需证据和建议路径；未经用户确认，不擅自扩展读取范围或启动外部执行。

### 9.3 用户确认

- AI 可以整理“可选方向”，但标题必须是“可考虑方向”或“需要你判断”，不能写成“本周最重要的三件事”。
- 用户确认的是自己的判断，包括问题、预期结果、验证证据、本周承诺和本周不做。
- 用户可以确认 0 至 3 项；“本周暂不新增重点，先完成既有承诺”是有效结果。
- 教练流程不得修改既有任务的状态、优先级、计划时间或完成状态。

### 9.4 重新打开已确认判断

- 用户可以在本周内重新打开已确认记录并查看判断。
- 本期可从弹窗打开对应 Markdown；已确认判断的差异编辑与再次确认留到后续版本。

## 10. 数据闭环与记忆层

### 10.1 周度记录

默认写入：

`05_Reviews/Weekly/2026-W31 周度重点.md`

周次随当前自然周变化。该文件是用户周初/周中确认的决策基线，与自动生成的 `日志/每日所思/02_每周复盘/2026-Wxx.md` 分开保存。本期不修改既有自动周复盘文件，也不写入其 `AI_AUTO_START` / `AI_AUTO_END` 自动生成区域。

### 10.2 用户可见字段中文规范

所有用户可见的记录字段名、状态值和枚举值必须使用中文，不出现仅供机器理解的英文值。

| 中文字段 | 允许的中文内容示例 |
| --- | --- |
| 类型 | 周度重点 |
| 周次 | 2026-W31 |
| 状态 | 草稿 / 已确认 / 已结束 |
| 关联目标 | Obsidian 内目标链接列表，可为空 |
| 关联任务 | Obsidian 内任务链接列表，可为空 |
| 创建方式 | ATL 思考教练 / 用户手动 |
| 确认时间 | 用户确认后的本地时间，可为空 |
| 复盘状态 | 待复盘 / 已复盘 |

不得使用 `type`、`week`、`status`、`goal_refs`、`task_refs`、`created_by`、`confirmed_at`、`review_status` 等英文键，也不得用 `weekly_focus`、`confirmed`、`pending` 等英文值呈现给用户。

### 10.3 周度记录正文

记录至少包含：

- 本周真正想解决的问题；
- AI 已了解的背景：事实、假设、缺失信息、资料来源；
- 教练启发：关键问题、反问、暂缓方向；
- 考虑过的方案；
- 用户最终判断；
- 希望产生的结果和验证证据；
- 本周承诺；
- 本周不做；
- 周末实际结果、价值判断、被验证或推翻的假设；
- 下周继续、调整或停止。

默认只保存结构化总结和影响最终判断的关键回答，不保存完整聊天逐字稿。AI 观察必须与用户原话、用户确认结论分开标识。

### 10.4 复盘回流

- `v0.7.0` 只提供周度记录与人工复盘区。
- 周复盘自动对照、月度/季度聚合，以及将已确认复盘结论作为下一次教练背景，统一进入后续增强范围。
- 后续增强跟踪：[Issue #87](https://github.com/PANGKAIFENG/agent-task-loop/issues/87)。

## 11. 模块拆解与输入输出

| 模块 | 主要输入 | 主要输出 | 产品职责 |
| --- | --- | --- | --- |
| 首页教练入口 | 当前周次、周度记录状态 | 入口状态、最近进展、主操作 | 让用户知道是否需要开始、继续、确认或复盘 |
| 上下文授权 | 用户选择、可用资料概览 | 本次授权范围 | 控制哪些个人资料可进入本次 AI 对话 |

| 问题引导 | 背景研究结果、用户回答 | 当前关键问题 | 逐步启发，避免长问卷和机械评分 |
| 方案整理 | 已澄清信息、用户偏好与约束 | 可选方向、依据、代价、验证方式 | 帮助比较，不代替决策 |

模型服务复用 ATL 现有的 Claude Code / CC-Switch 继承模式或自定义 Model 与 Base URL 配置，不新增 API Key 输入或第二套密钥存储。

## 12. 人工接管机制

- 所有最终判断和正式周度记录都必须由用户确认。
- 用户可以随时纠正 AI 的事实分类、删除不希望保留的内容、修改总结或停止对话。
- 用户拒绝提供敏感上下文时，AI 继续基于较少资料工作，并明确结论限制。
- 用户明确表示暂不决定时，可保存草稿离开，不强行收敛出三件事。
- AI 失败后保留用户输入、已授权范围、已确认事实和人工编辑内容；用户可重试、换模型配置或直接人工填写周度记录。
- 即使 AI 完全不可用，用户仍可从空白中文模板创建、编辑和复盘周度重点。

## 13. 异常与边界

| 情况 | 系统行为 | 不允许发生 |
| --- | --- | --- |
| 没有目标或 OKR | 说明缺失，先从当前责任、项目压力或希望改变的结果开始 | 编造用户目标 |
| 授权上下文为空 | 允许仅基于用户输入对话，并明确依据有限 | 静默扫描整个 Vault |
| 资料互相冲突 | 将矛盾列入信息缺口并附来源，请用户判断哪项有效 | AI 私自选择一种作为事实 |
| 用户输入很模糊 | 先确认问题范围，再提出一个高价值问题 | 直接生成 Top 3 |
| 用户要求直接给答案 | 可提供候选方向与理由，但仍标明由用户判断 | 冒充用户完成确认 |
| 模型未配置或不可用 | 显示配置状态；允许人工创建记录 | 阻塞首页或任务看板 |
| AI 超时或返回不可用内容 | 保留输入并允许重试；不推进状态 | 写入空白或错误的正式记录 |
| 上下文读取被拒绝 | 标记未授权资料并继续降级 | 绕过授权读取 |
| 部分资料读取失败 | 显示成功与失败范围，允许基于部分资料继续 | 将部分结果标成完整研究 |
| 用户未确认 | 保存为草稿，首页显示“继续思考” | 创建任务或标记已确认 |
| 同一周已有记录 | 草稿继续编辑；已确认记录只读展示并可打开 Markdown | 静默覆盖人工内容 |
| 已完成周复盘 | 保留原周度判断，补充复盘结论 | 用事后结果改写事前判断 |
| 笔记中包含指令性文本 | 作为引用资料处理并标记来源 | 把资料内指令当成系统操作命令 |

## 14. 验收标准

1. “当前最值得推进的三件事”标题栏右侧出现教练入口；首页不常驻完整教练工作区。
2. 入口按本周未开始、未确认草稿、已确认三类用户动作分别显示“梳理本周重点”“继续本周思考”“查看本周判断”。
3. 用户可按次选择目标、项目、任务、日历和周复盘作为上下文，并能看到当前授权范围。
4. `笔记同步助手`和`每日所思`默认未勾选，每次教练会话均需用户显式授权。
5. 未授权资料不会被发送给当前模型，也不会出现在 AI 的来源列表中。
6. AI 背景摘要可区分事实、假设、缺失信息和资料来源，用户可以纠正。
7. 教练对话每轮突出一个关键问题，并提供回答并继续、调整授权、人工整理和暂存能力。
8. AI 提供的是可考虑方向、成立条件、代价、机会成本和验证方式，不直接输出“本周最重要的三件事”。
9. 用户可以确认 0 至 3 项；确认 0 项时可以保存“本周暂不新增重点”的有效判断。
10. 未经用户确认，系统不创建任务、不修改任务状态、不写入正式已确认记录。
11. 用户确认后生成独立周度记录，所有用户可见字段名和枚举值均为中文，并立即刷新首页三张重点卡片。
12. 周度记录包含背景、教练启发、方案、用户判断、预期结果、验证证据、本周承诺、本周不做和复盘区。
13. 默认持久化内容不包含完整聊天逐字稿，AI 观察与用户确认结论可明确区分。
14. 同一周重复进入时继续已有草稿或只读查看已确认记录；保存时不会覆盖周度文件受控区外的人工内容。
15. 周度记录预留人工复盘区，但本期不接入周/月/季度自动复盘消费者，也不生成任务建议。
16. AI 失败、超时、模型不可用、权限被拒或上下文部分缺失时，用户输入不丢失且可重试或人工继续。
17. AI 不可用时，个人首页、当前执行任务、TaskNotes 看板和人工周度记录仍可使用。
18. 模型沿用现有 Claude Code / CC-Switch 或自定义 Model 与 Base URL 配置，不新增密钥保存入口。
