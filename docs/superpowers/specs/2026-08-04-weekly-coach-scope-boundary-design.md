## 2. 背景与问题

当前本周思考教练已经支持上下文授权、渐进对话、动态重点草稿、会话恢复和正式周记录，但职责边界只停留在“不能替用户安排任务”。现有 Prompt 要求模型每轮提出“当前最有价值的问题”，结构化结果却没有标识问题属于周级决策还是任务执行，也没有专门保存任务级问题的字段。

因此，模型可能把“什么叫可用的 Skill”“应该使用哪些筛选维度”这类需要在具体任务中研究和产出的内容，当作本周对话的信息缺口继续追问。结果是本周教练从“是否值得在本周投入”滑向“具体怎样完成任务”，对话变长，也让用户无法明确当前阶段的目标。

本设计采用“Prompt 边界 + 结构化分流”的方案：周级问题才允许进入下一轮对话；任务级问题记录为“进入任务后待思考的问题”，随草稿和正式周记录保存，但不在本周对话中继续追问。

## 3. 产品目标

### 3.1 核心目标

本周思考教练只帮助用户形成周级投入判断：本周是否值得做、为什么现在做、希望产生什么结果、与其他承诺如何取舍，以及是否有足够时间和资源投入。

当对话遇到必须进入具体任务后才能解决的问题时，教练应停止深挖，保留问题，并把对话带回尚未澄清的周级判断；如果周级信息已经充分，则停止追问并允许用户确认。

### 3.2 用户价值

- 用户知道当前是在做周级取舍，而不是提前执行任务。
- 有价值的任务级思考线索不会丢失，进入任务时可以继续使用。
- 任务级问题未解决不影响确认本周重点。
- 正式周记录能够同时保留“为什么本周做”和“进入任务后还要想什么”，供周中执行与周末复盘使用。

### 3.3 成功标准

- “什么叫可用的 Skill”不得作为本周教练的下一轮问题。
- 该问题应进入“进入任务后待思考的问题”。
- 后续问题只能围绕目标关联、本周时机、周级结果、结果价值、机会成本或投入容量。
- 延后处理的问题随草稿恢复，并写入正式周度记录。
- 延后处理的问题不计入重点完整度，也不阻塞确认。

## 4. 非目标

- 不实现任务规划教练、任务拆解器或验收标准生成器。
- 不自动创建任务、修改任务状态、安排日历或触发 Agent。
- 不把任务级问题转换为待办或任务清单。
- 不建立跨周的问题追踪系统。
- 不使用关键词黑名单代替语义边界判断。
- 不改变现有目标、项目、任务、日历和复盘授权机制。

## 5. 职责边界

### 5.1 允许进入本周对话的维度

| 周级维度 | 教练要帮助用户判断的内容 | 示例 |
| --- | --- | --- |
| 目标关联 | 支持哪个季度、月度或阶段目标 | 这件事与当前最重要的目标有什么直接关系？ |
| 本周时机 | 为什么现在做，延期一周有什么影响 | 如果下周再做，会错过什么窗口或承诺？ |
| 周级结果 | 本周结束时希望形成什么变化 | 周五时看到什么结果，说明本周投入没有白费？ |
| 结果价值 | 结果帮助谁，价值是否足够 | 这个结果会减少谁的什么成本或风险？ |
| 机会成本 | 做它意味着暂停、推迟或放弃什么 | 为了完成它，本周明确不做哪件事？ |
| 投入容量 | 时间、人员、依赖和截止日期是否现实 | 现有时间和必须本人判断的环节能否支撑这个承诺？ |

“完成证据”仍是本周重点的可见字段，但只描述周级可观察结果，例如“周四前形成可供评审的 10 个候选清单”，不得展开为任务内部的详细验收清单。

### 5.2 必须停止追问的任务级内容

- 领域概念和口径定义，例如“什么叫可用的 Skill”。
- 具体解决方案、技术路线或工具选择。
- 详细验收标准、评分表和检查项。
- 执行步骤、任务拆解、人员分工和操作顺序。
- 需要在任务内部调研、试验或比较后才能得出的结论。

### 5.3 边界判断规则

教练在生成下一问题前必须判断：这个问题的答案，是为了决定“本周是否投入和如何取舍”，还是为了决定“任务具体怎样完成”。前者可以追问，后者必须延后。

任务级问题不能出现在 `assistantMessage`、`nextQuestion` 或 `background.gaps` 中作为待用户本轮回答的缺口。`assistantMessage` 可以说明该问题已被记录，但所有要求用户回答的问题只能出现在唯一的 `nextQuestion` 中。

## 6. 对话契约

### 6.1 模型输出

现有结构化结果增加两个必填字段：

```ts
type WeeklyCoachQuestionDimension =
  | '目标关联'
  | '本周时机'
  | '周级结果'
  | '结果价值'
  | '机会成本'
  | '投入容量';

interface WeeklyCoachDeferredTaskQuestionInput {
  relatedItemId: string | null;
  relatedFocus: string;
  question: string;
}

interface WeeklyCoachResult {
  // 现有字段保持不变
  nextQuestionDimension: WeeklyCoachQuestionDimension | null;
  deferredTaskQuestions: WeeklyCoachDeferredTaskQuestionInput[];
}
```

约束如下：

- `nextQuestion`、`questionReason` 和 `nextQuestionDimension` 必须同时有值或同时为 `null`。
- `nextQuestionDimension` 只允许六个周级维度，不提供“任务执行”枚举值。
- 单轮最多返回 3 个延后处理的问题。
- 如果模型识别到任务级问题，应放入 `deferredTaskQuestions`，不得继续追问。
- 如果只剩任务级问题，且当前重点四个周级字段已经完整，`readiness` 应为“可确认”。
- 如果仍有周级缺口，只能选择一个当前价值最高的周级问题继续。
- 如果 `nextQuestion` 与本轮或既有延后问题的标准化文本相同，结果校验应原子失败，不能重新向用户提问。

### 6.2 Prompt 边界

系统 Prompt 增加显式的两级问题判定、正反例和停止规则，并要求模型按以下顺序工作：

1. 吸收用户最新回答并更新已确认事实。
2. 识别其中的周级判断和任务级问题。
3. 将任务级问题写入延后处理列表。
4. 判断是否仍存在影响本周取舍的周级缺口。
5. 有周级缺口时只问一个；没有时停止追问。
6. 更新草稿时只填写已有依据的周级字段，不用任务方案补造完成证据。

Prompt 包含固定示例：

```text
可以追问：
“筛选 10 个 Skill 这件事为什么必须在本周完成？”
“它与周四前的另一个承诺相比，哪个结果更重要？”

不得追问：
“什么叫可用的 Skill？”
“应该用哪些维度筛选 Skill？”

正确处理：
将后两项记录为“进入任务后待思考的问题”，继续讨论本周价值和取舍。
```

## 7. 草稿数据与兼容

### 7.1 草稿结构

会话草稿增加独立列表：

```ts
interface WeeklyCoachDeferredTaskQuestion {
  id: string;
  relatedItemId: string | null;
  relatedFocus: string;
  question: string;
}

interface WeeklyCoachSessionDraft {
  // 现有字段保持不变
  deferredTaskQuestions: WeeklyCoachDeferredTaskQuestion[];
  protectedDeferredTaskQuestionKeys: string[];
}
```

服务层负责合并模型结果，不允许弹窗直接修改持久化数据：

- 优先使用有效的 `relatedItemId` 关联现有重点。
- 没有 ID 时，在应用本轮草稿操作后按标准化的 `relatedFocus` 匹配重点。
- 无法匹配时保留为“待关联问题”，不丢弃。
- 当 `focusedItemId` 有值时，本轮只接受可关联到该重点的问题；指向其他重点或无法关联的问题均不合并，按名称明确匹配当前重点的问题可重新绑定。
- 同一重点下按标准化问题文本去重。
- 每项重点最多保留 5 个问题；未关联问题最多保留 10 个。
- 用户可通过服务层编辑或删除问题；服务层把旧问题的标准化文本写为 SHA-256 保护键，不保存原始文本，后续模型结果不得恢复受保护的问题。
- 删除重点时，同时删除明确关联到该重点的问题；未关联问题不受影响。

### 7.2 向后兼容

- 继续接受 `draftVersion: 1` 的既有草稿。
- 旧草稿缺少 `deferredTaskQuestions` 时规范化为空数组。
- 旧草稿缺少 `protectedDeferredTaskQuestionKeys` 时规范化为空数组；已有值只接受 `sha256:<64 位十六进制>` 格式。
- 现有消息恢复、字段归属、删除保护和秘密脱敏逻辑保持不变。
- 新字段执行与现有草稿相同的长度限制、数量限制和秘密脱敏。
- 继续对话时，Prompt 必须包含已有延后问题，并明确标记为“已延后，不得再次追问”。

## 8. 界面设计

### 8.1 固定边界说明

在对话输入区说明文字中显示：

> 这里只讨论本周是否值得投入和如何取舍；具体方案会记录下来，留到任务中处理。

说明保持单行或自然换行，不新增教程卡片、步骤条或独立模式切换。

### 8.2 重点卡片

每项重点在“完成证据”下增加默认折叠区：

```text
进入任务后待思考（2）
  · 定义 Skill 的可用标准
  · 确定筛选维度与验证方法
```

- 数量为 0 时不显示该区域。
- 展开后允许用户编辑或删除单条问题。
- 该区域不显示必填错误，不参与 `仍需确认` 状态计算。
- 未关联问题统一显示在草稿栏底部的“待关联的任务问题”折叠区，允许编辑或删除。
- 不提供“创建任务”或“交给 AI”按钮，避免扩大本期边界。

### 8.3 正式周记录

正式记录的数据结构增加以下字段：

```ts
interface WeeklyFocusItem {
  // 现有字段保持不变
  deferredTaskQuestions: string[];
}

interface WeeklyFocusInput {
  // 现有字段保持不变
  unassignedDeferredTaskQuestions: string[];
}
```

`WeeklyFocusItem.deferredTaskQuestions` 序列化后在中文 `本周判断` 数据及正文中按重点保存：

```markdown
### 1. 筛选本周要交付的 Skill

**预期结果**：周四前形成可供评审的 10 个候选清单

**为什么是本周**：本周存在明确交付承诺

**完成证据**：候选清单已提交评审

#### 进入任务后待思考的问题

- 定义 Skill 的可用标准
- 确定筛选维度与验证方法
```

未关联问题写入 YAML 中文字段和正文中的独立中文小节“其他进入任务后待思考的问题”。正式记录解析器对旧记录缺失两个新字段的情况默认使用空数组，并维持受控区外人工复盘内容不被覆盖。

## 9. 状态流转

```text
用户回答
  -> 模型区分周级判断与任务级问题
  -> 任务级问题合并到延后列表
  -> 应用本周重点草稿操作
  -> 仍有周级缺口？
       是：只返回一个带周级维度的问题
       否：停止追问，允许确认
  -> 自动暂存会话草稿
  -> 用户确认后写入中文周度记录
```

延后处理的问题不是草稿缺失项，不改变 `WeeklyCoachDraftReadiness`。用户继续对话时，这些问题会作为“已经延后，不得再次追问”的上下文发送给模型。

## 10. 异常与安全

- 模型返回未知问题维度、字段不完整或超过数量限制时，沿用现有结构化结果校验并原子失败，不部分应用。
- 模型重复返回同一任务级问题时，服务层去重，不重复展示。
- 模型把已延后的问题再次作为 `nextQuestion` 时，标准化文本比较应拒绝本轮结果；语义改写由 Prompt 边界和回归用例约束，结构化维度仍必须是周级枚举。
- 模型失败、超时或用户取消时，不应用本轮草稿操作，也不丢失已保存的问题。
- 延后问题执行现有秘密脱敏，不允许凭据进入插件草稿或正式周记录。
- 本功能不读取新的资料来源，不改变真实 Vault 写入开关。

## 11. 测试与验收

### 11.1 单元测试

- Prompt 包含职责边界、六个周级维度、正反例和停止规则。
- 结构化 Schema 拒绝缺失或非法的 `nextQuestionDimension`。
- 结果校验拒绝把本轮或既有延后问题原样作为 `nextQuestion`。
- 任务级问题合并、关联、未关联、去重、数量上限、编辑和删除正确。
- 旧版草稿缺少新字段时可以恢复，新字段经过脱敏后持久化。
- 删除重点会删除明确关联的问题。
- 任务级问题不影响重点完整度和确认状态。
- 正式周记录使用中文字段和中文小节，按重点和未关联问题均可无损往返解析。

### 11.2 弹窗测试

- 输入区显示轻量边界说明。
- 有问题时显示折叠入口和数量，没有时不显示。
- 用户可以展开、编辑和删除，关闭重开后结果保留。
- 未关联问题显示在草稿栏底部。
- 不出现创建任务或 Agent 执行入口。

### 11.3 场景回归

使用纯合成资料模拟以下对话：

```text
用户：海哥的 4 个 Skill 和筛选 10 个 Skill 共用一套可用标准。
```

期望结果：

- “定义 Skill 可用标准”进入延后处理列表。
- AI 不继续追问可用标准的具体内容。
- 如果机会成本尚未明确，下一问题属于“机会成本”或“投入容量”。
- 如果周级字段已经完整，`nextQuestion` 为 `null` 且可以确认。

### 11.4 发布验证

- 使用 Node 24 运行相关测试、全量测试、类型检查和插件构建。
- 由独立代码审查检查 Prompt 边界、数据迁移、持久化和 UI 回归。
- 合并后发布 `v0.8.3`，安装到 ClawVault 时保留现有 `data.json`。
- 真实 Obsidian 只验证插件加载、已有草稿恢复、静态边界说明和折叠区布局；不得发送测试 AI 消息或修改用户真实本周重点。

## 12. 代码影响范围

- `src/obsidian-plugin/weekly-thinking-coach.ts`：模型契约、Prompt 和结果校验。
- `src/services/weekly-coach-draft.ts`：延后问题的数据结构、服务操作、兼容、脱敏和转换。
- `src/services/weekly-focus.ts`：中文周记录序列化与解析。
- `src/obsidian-plugin/weekly-thinking-coach-modal.ts`：边界说明、折叠列表、编辑和删除交互。
- `src/obsidian-plugin/styles.css`：复用现有教练视觉语言补充轻量样式。
- 对应的 service、modal 和 integration 测试文件。

不修改任务执行器、TaskNotes 集成、日历、同步助手采集、模型配置或个人首页其他模块。

## 13. 发布结果

完成后，本周思考教练负责把用户带到清晰的周级承诺；具体任务内部还要研究的问题会被可靠保留，但不会继续占用本周决策对话。用户可以先决定“这周做不做、为什么、做到什么结果”，再在进入任务时解决“具体怎么做”。
