# 同步助手任务标题质量与旧数据修复设计

## 目标

让“从同步助手获取待办”生成的任务标题更适合在 TaskNotes 看板中快速浏览，并为历史上缺少 `title` Frontmatter 的 ATL 任务提供一次性、可预览、由用户主动确认的修复能力。

## 已确认方案

- 新候选标题仍由现有 AI 提取流程生成，不增加第二次模型调用。
- 标题应是简短的行动短语，优先使用“明确动词 + 对象或成果”。
- 标题保留来源中的具体对象，不编造来源中不存在的项目、结果或承诺。
- 避免“处理一下”“跟进一下”“看看这个”“了解一下”等只有模糊动作、没有明确对象或成果的标题。
- 历史标题修复通过 Obsidian 命令主动触发，不在插件安装、升级或启动时静默执行。
- 修复前展示扫描文件数、识别到的任务数和可修复数；修复后展示成功数和跳过数。

## 新标题规则

AI 输出的 `title` 增加以下约束：

1. 使用来源语言，写成可执行、可辨认的行动短语。
2. 优先使用“调研、评估、整理、设计、补齐、确认、尝试、跟进”等明确动作，加上具体对象或预期成果。
3. 建议 8 到 30 个中文字符，硬上限从 200 收紧到 60 个字符。
4. 不把整段背景复制成标题，不添加来源中没有的信息。
5. 当来源只有模糊动作且无法识别对象时，不生成候选。

确定性 `#待办` 兜底逻辑保持不变，避免本次修改扩大到既有召回与去重行为。

## 旧任务修复范围

扫描范围固定为：

```text
10_Tasks/Inbox/**/*.md
10_Tasks/Active/**/*.md
10_Tasks/Archive/**/*.md
```

只有同时满足以下条件的文件才是可修复项：

- Frontmatter 中明确存在 `type: task`；
- `title` 缺失、为 `null` 或仅包含空白；
- 正文存在有效的第一个 ATX H1，例如 `# 设计月度季度 AI 复盘扫描机制`；
- H1 不在 Markdown fenced code block 中。

修复时将第一个有效 H1 的文字写入 `title`。已有非空标题永不覆盖；正文、同步助手原文、钉钉日程、任务状态、项目和其他 Frontmatter 值不修改。操作重复执行时应得到零个可修复项。

## 交互

用户从 Obsidian 命令面板执行 `Agent Task Loop：修复旧任务标题`：

```text
命令 -> 只读扫描 -> 无可修复项：提示并结束
                 -> 有可修复项：打开确认弹窗
                    -> 取消：零写入
                    -> 确认：再次检查 Vault 管理权限并执行
                              -> 展示扫描数、成功数、跳过数
```

弹窗列出将要写入的标题和相对任务路径。修复期间阻止重复提交。文件在预览后若已被修改，执行阶段重新判断，不覆盖新的标题。

## 写入与安全

- 真实 Vault 写入继续要求插件设置中的 Vault 管理授权，并使用既有 `VaultWriteAuthorization` 边界。
- 扫描和写入只允许进入 `10_Tasks/Inbox`、`Active`、`Archive`，拒绝符号链接或逃逸路径。
- 写入通过 storage repository 完成，UI 不直接修改文件。
- 写入前重新读取并重新判定候选资格，避免覆盖预览后新增的标题。
- 修复完成后重建 `10_Tasks/任务索引.md`；若索引刷新失败，保留已完成修复并明确提示索引仍需刷新。
- 测试只使用临时 Vault fixture，不读取真实 ClawVault。

## 不在本次范围

- 不批量改写已有但质量一般的标题。
- 不调用 AI 重写历史标题。
- 不重命名历史任务文件。
- 不修改 TaskNotes 插件或 Base 配置。
- 不修改候选召回、去重、任务状态或自动执行逻辑。

## 验收

- AI 提取提示词与 JSON Schema 均体现简短、行动导向和不编造规则。
- 超过 60 个字符的 AI 标题被结构化校验拒绝。
- 只有 `type: task`、空标题、有正文 H1 的任务进入预览。
- 已有标题、无 H1、非任务文件和代码块内伪 H1 均不修改。
- 缺失、`null`、空字符串标题均可从第一个有效 H1 修复。
- Frontmatter 其他内容和正文保持不变，文件不被重命名。
- 取消操作零写入；重复执行幂等；执行前权限关闭时零写入。
- 聚焦测试、完整测试、类型检查、Lint 和构建全部通过。
