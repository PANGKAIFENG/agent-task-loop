# 收件箱日期排序与每日待办不限量设计

## 目标

让任务总看板的收件箱能够直接回答两个问题：

1. 这条待办来自哪一天的原始记录？
2. 这条待办是什么时候被 ATL 整理进收件箱的？

同时取消每日复盘“最多向 ATL 提交 3–5 条候选”的业务限制。所有通过任务质量判断且尚未完成的待办都可以进入 Inbox，继续保持候选状态并由用户人工处理。

## 已确认方案

- 保留现有按任务状态分列的 TaskNotes 看板，不改成按日期分列，也不新增第二个时间线入口。
- 卡片同时展示“来源日期”和“入箱时间”，两者含义严格分开。
- 隐藏没有实际排期价值的 `scheduled: false`；存在有效排期时仍可展示计划时间。
- 用户拖动形成的人工顺序优先；没有人工顺序的任务按入箱时间从新到旧排列，再按来源日期和优先级排序。
- 每日复盘不再设置 3–5 条数量上限；是否进入 Inbox 只由任务质量、来源证据、完成状态和去重结果决定。
- 所有每日复盘生成的任务继续写为 `status: inbox`、`review_state: candidate`、`auto_executable: false`，不自动进入待执行、日历或 Agent 队列。

## 日期语义

### 来源日期

`source_date` 表示待办对应的原始笔记日期，例如同步助手消息所在的自然日。它用于回答“这件事是在哪一天被记录或识别出来的”。

- ATL 收集任务继续使用现有 `source_date`。
- 手工任务或历史任务没有 `source_date` 时保持空值，不使用文件时间伪造来源日期。
- 卡片字段显示名为“来源日期”。

### 入箱时间

`created_at` 表示任务首次由 ATL 创建并进入 Inbox 的时间，用于回答“这件事是什么时候被整理进任务系统的”。

- 标准 ATL 任务直接使用 `created_at`。
- 旧任务或 TaskNotes 手工任务缺少有效 `created_at` 时，Base 公式回退到 `file.ctime`。
- 回退值只用于显示和排序，不回写任务 Frontmatter。
- 卡片字段显示名为“入箱时间”。

### 计划时间

`scheduled` 仍表示用户计划在哪一天或哪个时间段处理任务，与来源日期、入箱时间无关。

- `scheduled: false`、空字符串和缺失值均视为“未排期”，卡片不显示。
- 有效日期或日期时间通过一个可空公式显示为“计划时间”。
- 本次不修改任务的排期字段，也不改变日历视图规则。

## 看板呈现与排序

任务总看板继续按 `status` 分为收件箱、待执行、执行中和已完成等列。任务总看板、工作任务、个人实践和待归类四个 ATL 已管理的看板视图统一调整卡片字段为：

```text
project_id
source_date
formula.atlCollectedAt
formula.atlPlannedAt
priority
```

其中：

- `formula.atlCollectedAt`：优先返回 `date(created_at)`，无有效值时返回 `file.ctime`。
- `formula.atlPlannedAt`：仅在 `scheduled` 是有效日期时返回日期，否则返回空值。
- 不再直接展示原始 `scheduled` 字段，因此不会出现 `scheduled: false`。

卡片示意：

```text
补齐 agent-task-loop README 首屏
项目：个人任务系统 · 优先级：普通
来源日期：2026-07-24
入箱时间：2026-07-25 20:03
```

排序顺序固定为：

1. `tasknotes_manual_order DESC`：保留用户拖动结果。
2. `formula.atlCollectedAt DESC`：未人工调整的任务优先显示最新入箱项。
3. `source_date DESC`：同批次任务按来源日期从新到旧。
4. `formula.atlPriorityRank ASC`：最后按紧急、高、普通、低排序。

日期只作为卡片信息和自动排序依据，不成为新的任务状态，也不改变工作/个人实践分类。

## 每日待办生成规则

现有每日复盘自动化中的“每日最多向 ATL 提交 3–5 条候选”整条删除，不设置新的数量上限。

实时扫描和每日复盘统一使用以下分类口径：

- `explicit_task`：来源明确要求执行、安排、输出或跟进的未完成事项。
- `inferred_task`：没有直接命令句，但上下文存在明确行动目标和充分推断理由。
- `supporting_action_candidate`：与当前目标直接相关、值得单独跟踪的关联调研或支撑动作。
- `thought_or_context`：观点、策略思考、困扰或背景，没有形成可执行动作。
- `information`：资讯、文章、概念、链接或素材记录。
- `completed_action`：来源已经说明完成、交付或不再需要执行的事项。

前三类可以成为任务候选；后三类只留在每日整理或来源记录中。分类结果必须继续保留原始的一次性或周期性意图、动作对象、预期成果和时间表达。

每条待办仍必须逐条通过以下质量门槛：

1. 来源中存在尚未完成的明确行动，或存在有充分理由的推断行动。
2. `sourceQuote` 能在对应来源记录中找到。
3. 标题包含明确动作和对象或预期成果，不使用纯观点或泛化表达。
4. 推断待办必须在正文中写明推断理由。
5. 纯资讯、情绪、阅读触发、已经完成的行动和没有行动意图的观察不得进入 Inbox。
6. `#Ai使用` 等主题标签不能单独作为待办证据。
7. 周期性任务保留原始频率和时间，不得为了去重改写成一次性任务。
8. 相同任务返回已有任务；同一来源但动作不同的任务分别保留；标题相似但任务类型不同的任务不得静默合并。

实时“从同步助手获取待办”仍保留候选勾选弹窗，只有用户勾选的项目进入 Inbox。每日复盘是后台流程，其所有合格候选通过 ATL 收集服务进入 Inbox，但仍需用户在 Inbox 中确认后才能成为正式待执行任务。

模型每批最多处理 40 条来源记录、总正文最多 60,000 字符是技术分批限制，不是待办输出数量限制。本次保留分批机制，合并全部批次的合格候选。

## 组件修改边界

### `board-appearance-controller`

- 增加“入箱时间”和“有效计划时间”公式所需的 Base 配置。
- 更新推荐卡片字段与排序常量。
- `status()` 按新的预设判断是否已应用。
- `applyRecommendedPreset()` 继续先创建原始 `.atl-backup`，再原子更新 Base。
- 只更新任务总看板、工作任务、个人实践和待归类四个 ATL 已管理视图的卡片字段与排序。
- 保留这四个视图各自的筛选条件、状态分列、列宽和其他设置；不修改任意用户自建视图或日历视图。

### 每日复盘自动化

- 原地更新现有 `id = "obsidian"` 自动化，不创建重复自动化。
- 删除 3–5 条数量限制以及“超过 5 条只保留最强候选”的规则。
- 保留现有三分法、ATL 收集命令、来源校验、跨入口去重、失败报告和人工确认边界。
- 运行报告继续输出候选数、ATL 新增数、已有数和失败数，不截断候选列表。

### 文档

- 用户操作文档说明来源日期、入箱时间和计划时间的区别。
- 说明推荐看板预设会隐藏无效的 `scheduled: false`，并保留人工拖动顺序。
- 说明每日复盘不再限制候选数量，但 Inbox 中的任务仍是待确认候选。

## 兼容性与异常处理

- 历史任务缺少 `source_date`：来源日期留空，仍可按入箱时间排序。
- 历史任务缺少或损坏 `created_at`：使用 `file.ctime` 显示和排序，不写回文件。
- `scheduled` 为 `false`、空字符串、缺失或不可解析：计划时间留空，不影响卡片加载。
- 用户已经拖动任务：人工顺序保持最高优先级，不因入箱日期改变。
- Base 文件结构无效、存在多个同名任务总看板或路径不安全：沿用现有失败关闭策略，零写入并显示错误。
- 自动化某条候选提交失败：每日整理仍可完成，明确报告失败，不直接写任务 Markdown。

## 测试策略

遵循 TDD，测试只使用临时 Vault 和合成内容：

1. 先更新 `board-appearance-controller` 单元测试，使旧预设测试失败。
2. 验证推荐预设包含双日期、可空计划时间和新的排序顺序。
3. 验证 `scheduled: false` 不再作为原始字段出现在卡片顺序中。
4. 验证四个 ATL 已管理视图统一获得新卡片字段和排序，同时各自筛选条件保持不变。
5. 验证已有备份、用户自建看板视图和日历配置保持不变。
6. 使用合成回归样例覆盖：不该生成的观点、应生成的关联调研、周期任务类型保持、同源不同动作不误合并。
7. 验证超过 5 条的合格合成待办不会被截断，并全部通过 ATL 保持 `inbox/candidate/false`。
8. 运行聚焦测试、完整测试、类型检查、Lint 和构建。

真实 Vault 只在显式设置 `ATL_VAULT_ROOT` 和 `ATL_ALLOW_REAL_WRITES=1` 后验证。验证时先备份当前 Base，只检查任务总看板配置和显示结果，不改动同步助手原文、任务状态、钉钉日程或历史任务字段。

## 不在本次范围

- 不新增按日期分列的第二个看板或收件箱时间线页面。
- 不实现日期分组标题或状态列内的二级分组。
- 不批量补写历史任务的 `source_date` 或 `created_at`。
- 不改变 TaskNotes 插件源码或调用其私有 API。
- 不自动确认、排期、执行或归档 Inbox 任务。
- 不增加第二轮模型审核或新的模型调用。

## 验收标准

1. 收件箱卡片能看到来源日期和入箱时间，字段含义不混淆。
2. 缺少 `created_at` 的旧任务使用文件创建时间参与显示和排序，且任务文件不被改写。
3. 未排期任务不再显示 `scheduled: false`，有效计划时间仍能显示。
4. 用户拖动顺序优先；未拖动任务默认按入箱时间从新到旧排列。
5. 四个 ATL 已管理看板的 Inbox 卡片呈现一致；现有状态列、工作/个人分类、项目、优先级和日历行为保持不变。
6. 每日复盘不再因 3–5 条上限丢弃合格待办。
7. 超过 5 条的合格待办均进入 Inbox，且全部保持 `candidate`、不可自动执行。
8. 纯资讯、观点、已完成事项和无行动意图内容仍不会进入 Inbox。
9. 实时扫描仍由用户勾选，后台每日复盘仍只通过 ATL 收集服务写任务。
10. 测试、类型检查、Lint 和构建全部通过。
