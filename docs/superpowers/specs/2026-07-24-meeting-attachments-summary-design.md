# 会议附件与分析结果页设计规格

## 1. 背景

ATL v0.6.0 已能从钉钉日程创建会议笔记、粘贴听记、生成摘要/结论/待办候选，并把用户勾选的候选加入 Inbox。当前流程仍要求把所有内容粘贴到一个文本框，分析后关闭原弹窗并跳到另一个候选弹窗；用户无法直接关联听记文件、补充资料，也无法再次打开会议时查看结构化总结。

本期扩展 ATL 自己的 Obsidian 原生弹窗，不修改或 fork TaskNotes，不向 TaskNotes DOM 注入按钮。

## 2. 目标

1. 在“添加会议听记”弹窗中从本机选择文件并复制到当前 Vault。
2. 支持把 `txt`、`md`、`docx`、`pdf` 导入为听记原文或选作分析资料。
3. 图片、音频、视频及其他格式可以作为本地附件保存，但不解析、不发送给模型。
4. “保存并分析”完成后保留同一个弹窗并切换到结果页。
5. 结果页展示摘要、关键结论、带来源引文的待办候选、已关联资料、可折叠原文、模型和状态。
6. 分析结果和附件关系持久化到同一份会议 Markdown；再次打开时优先展示已有结果。
7. 原文、分析资料或“用于分析”选择变化后保留旧结果并标记陈旧，只有用户点击“重新分析”才覆盖 ATL 管理的旧结果。

## 3. 不做范围

- 不 OCR 图片，不转写音频或视频。
- 不解析 `pptx`、`xlsx`、网页、邮件或压缩包。
- 不自动上传未勾选的关联资料。
- 不自动重新分析，不自动选择、创建或执行待办。
- 不修改钉钉日程镜像，不把会议内容写回钉钉。
- 不实现跨会议人物画像、绩效评价或长期组织分析。
- 不修改 TaskNotes 插件文件、弹窗或内部数据。

## 4. 用户流程

### 4.1 新会议

1. 用户从有效钉钉日程的文件菜单选择“添加会议听记”。
2. 弹窗展示会议类型、参与人和听记原文。
3. 用户可以直接粘贴原文，也可以点击“从文件导入原文”选择一个 `txt/md/docx/pdf`。导入文件会填充原文并作为附件保存，原文默认参与分析。
4. 用户可以点击“添加关联资料”选择多个任意格式文件。
5. 可解析资料显示“用于本次分析”复选框，默认关闭；不可解析资料只显示“仅保存附件”。
6. “仅保存”落盘后关闭弹窗；“保存并分析”先落盘，再在同一弹窗显示分析中状态。
7. 模型调用前明确提示：原文以及用户勾选的资料文本将发送到当前配置的模型服务。
8. 分析完成后切到结果页；待办候选默认全部不选，只有用户点击“将所选任务加入 Inbox”才写入任务系统。

### 4.2 已有会议

1. 再次从同一钉钉日程打开时，ATL 根据稳定事件哈希找到原会议笔记，不新建重复文件。
2. 已有有效分析时默认展示结果页，用户可切回“编辑资料”。
3. 已有失败或未分析状态时默认展示编辑页，并提供分析/重试入口。
4. 当前分析输入与上次成功输入不一致时，结果页显示“内容已更新，建议重新分析”；旧摘要仍可查看。
5. 用户点击“重新分析”后才替换 ATL 管理的分析区域，人工写在管理区域外的内容保持不变。

## 5. 文件与数据模型

### 5.1 附件目录

附件保存在会议笔记月份目录下：

```text
08_Meetings/YYYY-MM/attachments/<event-hash>/<content-hash-prefix>-<safe-name>
```

- `event-hash` 取钉钉事件稳定哈希，不含 `sha256:` 前缀。
- 文件名只保留安全字符并带内容哈希前缀；同内容重复添加复用同一路径。
- 选择文件只复制到 Vault，不移动或修改原文件。
- 从关联列表移除只解除会议关系，本期不自动删除已复制文件，避免误删被其他笔记引用的资料。

### 5.2 会议 Frontmatter

保留现有字段并增加：

```yaml
attachments:
  - id: sha256:<full-hash>
    name: interview.pdf
    path: 08_Meetings/2026-07/attachments/<event-hash>/<prefix>-interview.pdf
    media_type: application/pdf
    size: 12345
    role: transcript
    analyzable: true
    include_in_analysis: true
analysis_status: pending | failed | ready_for_confirm | stale
analysis_input_hash: sha256:<hash>
analysis_model: inherit | <configured-model>
analysis_updated_at: <ISO timestamp>
```

附件列表只保存元数据和 Vault 路径，不把二进制或解析全文写入 YAML。听记原文、可读分析结果和内部结构化分析快照继续保存在 ATL 管理区域。结构化快照使用隐藏、编码后的 JSON 注释，供弹窗可靠恢复；它不进入日志、Git 或其他外部系统。

### 5.3 分析输入指纹

输入指纹由以下内容按稳定顺序组成：

- 当前会议元数据；
- 当前听记原文；
- 每个 `include_in_analysis: true` 的可解析附件路径及当前文件内容哈希。

成功分析时写入 `analysis_input_hash`。再次读取或提交时重新计算；不一致即视为 `stale`。附件显示顺序或未选附件变化不影响指纹。

## 6. 文档解析

- `txt` / `md`：严格按 UTF-8 解码，去除 UTF-8 BOM，保留正文换行。
- `docx`：使用 `mammoth.extractRawText`，只取纯文本，不渲染 HTML，不执行宏或外部资源。
- `pdf`：使用 `unpdf/pdfjs` 的 serverless PDF.js `getDocument`，逐页读取 `getTextContent()` 并合并纯文本；不渲染页面、不 OCR、不加载远程字体。
- 扩展名大小写不敏感；文件类型判断以安全扩展名为主，MIME 仅用于展示。
- 单文件最多 50 MiB；每个文档解析结果最多 100,000 字符，单次发送给模型的所有来源合计仍受 100,000 字符上限约束。
- 关联资料添加时不解析，只有显式勾选并开始分析时才解析；PDF 逐页读取，达到字符预算立即终止，并限制为最多 500 页、100,000 个文本项。
- DOCX 在调用 Mammoth 前流式累计 ZIP 条目的实际解压字节，超过 64 MiB 时立即终止并拒绝解析。
- 空文档、加密/损坏文件、非 UTF-8 文本和解析异常均显示稳定中文错误，文件不会自动加入分析输入。

## 7. 分析输出与引用

模型输入按来源分段：`会议听记` 为固定主来源，其他选中资料使用原文件名作为来源名。模型必须为每个待办候选返回 `sourceName` 和逐字 `sourceQuote`。ATL 同时校验来源存在且引文确实出现在该来源文本中；校验失败时不写入分析结果。

结果页包含：

- 状态与模型；
- 摘要；
- 关键结论；
- 待办候选、来源名和原文引用；
- 已关联资料及是否参与本次分析；
- 默认折叠的会议听记原文；
- “编辑资料”“重新分析/重试”“将所选任务加入 Inbox”“关闭”。

待办候选仍使用现有 `origin: obsidian_meeting`、`reviewState: candidate`、`autoExecutable: false` 和稳定来源键；默认不勾选，重复提交保持幂等。

## 8. 并发与失败处理

- 同一路径同时只允许一次分析。
- 保存附件失败时不更新会议附件元数据。
- 解析失败不会暴露解析器堆栈或文件正文，只显示文件名和稳定错误。
- 模型失败后保留原文、附件、人工内容和旧分析；状态为 `failed` 或 `stale`，允许用户重试。
- 分析期间原文、分析选择或文件内容变化时不写入过期结果，提示用户重新分析。
- 更新只替换 ATL 管理的听记/分析区域和已定义 Frontmatter 字段，不覆盖管理区域外的人工笔记。

## 9. 验收标准

1. 用户无需终端即可导入原文文件、关联多个资料并保存到 Vault。
2. `txt/md/docx/pdf` 使用真实解析库获得文本；其他格式仅保存且不能勾选分析。
3. 未勾选的关联资料文本不会出现在模型 prompt。
4. 分析前有清晰的发送范围提示，分析后弹窗停留并展示完整结果。
5. 关闭后再次打开同一日程能恢复附件和结构化总结。
6. 原文或分析资料变化能显示陈旧状态，且不自动覆盖旧总结。
7. 候选引用按来源校验，默认不选，只有明确勾选项进入 Inbox。
8. 钉钉镜像、TaskNotes 插件文件和会议笔记人工区域保持不变。
9. 单元、集成、类型、Lint、构建和合成 Vault 冒烟全部通过；测试与 Git 不包含私人会议资料。
